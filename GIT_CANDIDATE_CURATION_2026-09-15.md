## Admission rules

### Include by default, after content review

- Human-readable `README`, method, protocol, theorem, report, erratum, and
  adjudication documents.
- Canonical source, hostile/independent source, focused tests, and deterministic
  verifier programs.
- Compact final results, exact source freezes, manifests, checksums, gate
  decisions, and bounded execution records needed to authenticate a claim.
- Dependency lockfiles and infrastructure-as-code that contain no live account
  or resource identifiers.
- Compact obstruction records that explain a scientifically relevant failed
  gate or change in method.

An `AUDIT_` prefix is not by itself sufficient for inclusion. The record must
identify its authority, inputs, method, terminal decision, and relationship to
the canonical successor.

### Exclude from Git; retain externally if custody requires it

- Numerical `CACHE_PAYLOADS*` and `WORKSPACES*` trees, including version-prefixed
  V004R4 forms.
- Raw arrays and intermediate shards that are reproducible from admitted code
  and inputs.
- Nested copies of entire development/audit trees preserved inside failed-run,
  retirement, or wall-policy custody folders.
- Packaged Python runtimes, wheelhouses, and generated source-bundle archives.
- Raw AWS instance allocation, discovery, launch-journal, user-data, and live
  stack-input snapshots.
- Duplicate progress logs and repeated failed-attempt workspaces when a compact
  terminal obstruction record plus a hash inventory preserves the provenance.

Exclusion from Git is not deletion. A scientifically necessary large object
should have an external immutable location, SHA-256, byte count, media type,
producer command, and a small Git-tracked custody record.
