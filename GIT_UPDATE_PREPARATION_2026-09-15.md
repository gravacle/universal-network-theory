## Explicit-allowlist staging discipline

No commit should be assembled with `git add .`, a directory-wide add, or an
automatic whole-worktree archive. For each proposed commit:

1. Write and review an exact path allowlist for that scientific custody unit.
2. Confirm the index is empty, then stage only those named paths with
   `git add -- path/to/allowlisted-file ...`.
3. Review `git diff --cached --name-status`, `--stat`, `--check`, and
   `--summary` against the allowlist.
4. Refuse cache/workspace/runtime/bundle, progress/log, live AWS, and duplicated
   custody paths unless the review record names and justifies an exception.
5. Run staged-blob size, credential-pattern, JSON, manifest-hash, and relevant
   scientific test checks before authorizing a commit.
