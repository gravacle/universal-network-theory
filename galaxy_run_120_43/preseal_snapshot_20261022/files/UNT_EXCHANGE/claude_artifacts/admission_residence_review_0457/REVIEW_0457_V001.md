## Notes for root (not defects)

1. **The read-integral diagnostic will be exactly 0 under V003.** read_rows builds every read from z = _z_bytes(dom, info, inc), i.e. incidence and presence only (V003 L1970-1983, lead-verified). Admission changes only the p and s bits. The residence change appears in D and Da. If a visible residence diagnostic is wanted, sum dt (D_new - D_old) or the Da integral from the existing segment fields would be informative with no new formula. Root's choice.
2. **Under V003, N_fwd = N_rev = 1 and every event-W term is 0**, so log R = -sum dt dD. The dD comes from v's diagonal owners: epsilon_c p_v, E_S/E_R and lambda_J d_v p_v. The move is legal only where (p_v, s_v) is constant over the whole path, kappa_v != 0 with a positive multiplier, and, in the admit_rev direction, there is no bind at v. Paths where v changes status mid-path belong to the existing kappa-pair and regrowth moves.
3. **Root integration conditions:**
   - select this move with a fixed, path-independent probability;
   - keep a palette binding, so that run['group'] exists;
   - treat budget, cap and enumeration stops as terminal, never as rejections and never resumed with fresh randomness. V006 is resumable=False.
4. **INTERFACE_0456_V001 wording.** It says only attempt-level counters can be written before an interruption. In fact `<kind>_selected`, the rejection reasons, `legal_transport` and `last_proposal` (L97, L135-137) are also written before the commit checkpoint, as in Birth. This affects diagnostics only; the path is never touched.
5. **A18i, inherited from Birth L86.** If two D-difference terms overflowed with opposite signs, math.fsum would raise a raw ValueError ("-inf + inf in fsum") before the module's finite check at L133 could convert it to _Stop. The input path is unchanged. This needs |D| near 1e308 and cannot come from real energies. Optional hardening would check each term before fsum.
6. **_keys_equal on owner tuples is consistent with the pinned base.** V004 L2125-2136 is `a == b` with a single-bool guard, and V004's _unique_mark compares owners the same way (L3215). Claude3's 7k non-pass came from a stricter-than-pinned probe and is not a defect.
