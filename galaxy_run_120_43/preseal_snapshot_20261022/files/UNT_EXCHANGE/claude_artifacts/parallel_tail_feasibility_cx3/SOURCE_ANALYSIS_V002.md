`date -u`: Sun Oct 18 19:51:55 UTC 2026.

TESTED: source inspection and byte-pinned prototype execution on saved synthetic K32/K128 and saved C4R3 K32. C4R3 K128 and fresh-process threading comparisons are in progress; their eventual immutable results, not this source note, determine numerical verdicts. This successor supersedes the historical execution block in SOURCE_ANALYSIS_V001.md. A95 permits default priority after the recorded sandbox taskpolicy refusal and authorizes VECLIB6 only for nonproduction measurement. No production driver or module was changed.

The independence/summation analysis in the historical note remains applicable. The selected process split is the native stellar transform's existing 256-frequency quadrature batches. Each batch has independent output cells. Its global nodes, kmax, provider expression, matrix shape, component order, doubling order, accumulator += and final global certificate are unchanged. The parent waits for each batch in original index order and populates the existing exact-k cache, then calls unmodified v002 build. The full cold timer includes fresh roster creation, grid/preparation, worker creation and teardown, and native build. Total CPU is self plus reaped-child CPU, including startup. Jet comparison cost is separately reported.

Radius splitting and shell splitting were analyzed, not implemented: changing GEMM output row counts or grouping partial sums can change floating-point bytes. Native main quadrature blocks are independent before reduction, but serial-order reduction of their full ring increments would incur large IPC: K256,72 radii,102400 kz gives353,894,400 bytes per original block, before corner/shell data. The chosen stellar batches return only short vectors. Native gas, source contractions, ring/corner/shell assembly and on-demand jet arithmetic remain unchanged. Spherical residual and other stage kinds were not numerically exercised by this rotation-only prototype.

Workers are configured caps (2,6,12), not an assertion of simultaneous activity. PID participation is measured per component/doubling pool; total distinct PIDs across separate pools is not concurrency. Native batch counts bound utilization: compact synthetic K32 has3 batches/pass, K12811; saved C4R3 K32 has21. Memory values are observed RSS and conservative scratch estimates, not OS hard allocation limits. All measured processes must remain below8 GiB and all individual workers use BLAS1.

Thread comparison uses separate fresh processes with VECLIB_MAXIMUM_THREADS=1,6,6 and the other five numerical thread environment variables fixed at1. It directly compares dtype, shape and bytes of every state array and every order1/order2 jet array, plus record/digest. Configured VECLIB caps do not establish actual thread utilization or universal determinism.

The v003 source exists, but driver_r6 has no BUILD/BUILD.md at this inspection. Its optional cache remains source-only here. The stars cache key includes module/provider/runtime/config and registered source profile custody; vertical/source-dependent data are excluded from persistent caching. Prepopulating the native star cache causes BYPASS_IN_PROCESS_CACHE rather than publishing a persistent stars entry. A future r7 must insert parallel computation into the cold-cache miss path before storing, preserving the existing certificate and cache-side effects. The current cache's os.rename and rmtree cleanup conflict with this session's immutable-write rule, so no persistent-cache execution occurs. Cache hits and process splitting target overlapping work; their savings must never be simply added. No source inspection of v003 establishes its adoption; r5 remains the sealed object per coordinator.

C4R3 is component replay only: exact pinned saved rotation arrays, registered DDO154 source profile, fixed physical inputs, test-only certificates, and72 radii. Its pinned prior I1T PASS is carried rather than independently rerun. No solve, route/worker main, scientific launch, observed target or prohibited run is accessed. Synthetic fixtures establish arithmetic identity on their own compact grid and do not establish production cost.

Recommended follow-on is a narrow optional cold-stars process-count parameter, default1, in a new module/driver lineage. Preserve all batch shapes/order, keep BLAS1, bound outstanding futures, maintain source/provider custody and failure behavior, and perform independent byte proof on applicable saved stage/source classes. Source-integrated shared factors and main-block splitting are separate, larger changes. Build/review estimate is two focused passes plus measured replay runtime, not a promised elapsed completion time. Production adoption and KHI timing remain UNTESTED.
