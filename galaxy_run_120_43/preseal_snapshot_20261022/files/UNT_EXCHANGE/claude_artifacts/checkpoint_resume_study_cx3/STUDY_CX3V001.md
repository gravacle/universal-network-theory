## 3. Minimal successor design and proposed registration text

**FORMAL proposal only; not adopted, not implementation authorization.** Start with a single registered serial route-A continuation at a complete-column boundary. Keep same controls, seed/spec bytes, code/runtime pins, worker count, physics, arithmetic order and convergence/acceptance thresholds. Keep the checkpoint frontier fixed by the last valid commit, never by a favorable result. Stage-level continuation is a separate second increment; partial-column integration state is outside the initial design.

Use a new segment namespace with an immutable parent-checkpoint manifest and deterministic logical record identities. The reader must validate the complete ancestor closure, not just the last array. Preserve previous attempt trees, incomplete files and all failure records. No existing tree is reopened for new scientific writes. The current checkpoint implementation assumes one directory; a parent-aware reader/materializer is required. Pin seed/code paths or replace path identity only through a preregistered schema migration—copying to a new location can otherwise change identity.
