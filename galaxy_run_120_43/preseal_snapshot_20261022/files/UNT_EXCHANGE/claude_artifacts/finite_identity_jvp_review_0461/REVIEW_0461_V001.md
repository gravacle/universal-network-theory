## Required corrections (blocking; root and author action)

1. **B2. Core L9: `from scipy.special import jv` at module level.**
   - No interpreter on this machine has scipy, including the documented runtime (3.12.14, numpy 2.3.5) and the homebrew Pythons. Driver L63 therefore raises ModuleNotFoundError at `admission`.
   - `jv` is used only at core L82, inside `material_source_identity_jvp` (L30-97), which the driver never calls.
   - **Minimal fix:** move the import inside that function and save the result as a **new core version**.
   - (Option: a numpy J₀..J₇ validated over the real k⊥R range, which keeps the cheap analytic source path usable for future multi-direction JVPs. Claude4's verifiers prototyped a Miller-recurrence version accurate to 3.7e-16 for x≤60. Such a version needs its own review.)
2. **B1. Driver L13: `INPUTS_SHA = 'TO_BE_FROZEN'`.** L59 therefore raises `Pin mismatch` on every launch. The order of repair matters:
   - (a) the new core gets a new hash;
   - (b) write a new manifest whose `refs.core` carries the new path and hash. If the manifest is versioned rather than overwritten, **also update L12**, which hard-codes the manifest filename;
   - (c) freeze L13 to that manifest's sha;
   - (d) save the result as a **new driver version**, so the reviewed v001 bytes stay immutable.

   Do not freeze today's `d0c194f0…`; it becomes stale at step (b).
3. **B3. No monitor or recipe with fixed limits.**
   - The driver has only a MAC cap and a soft wall check inside `progress()`, which is called 13 times. That check never runs inside `prepare_geometry`, `exact_finite_sum`, the radial loop or the Σ stage.
   - The V002 monitor (25974dd6) is hard-wired to the producer.
   - **Provide a JVP monitor or recipe** with these settings:
     - `-I -B` and six thread variables set to 1;
     - wall 2400 s, RSS 4 GiB and output 1 GiB (expected peak about 0.9 GB and output about 110 MB);
     - `--point-chunk 128` and `--rank-relative-tolerance 1e-12` (the producer's values, on the same H);
     - `--max-inverse-complex-mac 12000000000`, written as integer digits because argparse `type=int` rejects `1.2e10`. The exact planned value on the real layout is 10,404,495,360. That layout is 5184 transverse pairs × 72 kz, 2304 columns and 73,728 points, read from the producer's own metadata;
     - `--max-wall-seconds` below the monitor cap.
   - **The receipt must key success on finish.json `status`.** The driver exits 0 on a handled failure.

## Required before launch: a frozen acceptance note (documentation only)

The completeness critic (J4) showed that the driver's only consistency check cannot accept or reject the JVP on this data. That check is the whole-residual tangent–secant comparison at one α = 9.96e-5 (L200-203).

- First-order part changes cancel strongly in the modal rows. Part-norm to residual-change ratios are as large as 37, 132, 3809, 19, 33 and 65 for m1..m6, taken from the pinned finite-run finish.json diagnostics.
- The per-part second-order error is O(α|G|), with 1−minJ = 0.0365.

So a **correct** JVP can show whole-residual mismatches from tens of percent to well above 100%, with m3 the worst.

Freeze an acceptance note with the repaired packet; it is part of the delta review. The thresholds proposed by Claude4 are:

**(a) Structural (a breach is a defect).**
- Hdot ≤ 1e-12 ‖H0‖.
- Σ JVP ≤ 1e-10 of the identity Σ norm.
- ‖m0_radial JVP‖ / ‖radial_fixed_Sstar_jvp‖ < 1e-6. A value ≥ 0.5 means a speed-elimination wiring failure.
- `F3_gradient_replay` < 1e-10.

**(b) Primary, computed per modal label (m1..m6) as part-level secants.** The finite worker saves the kinetic, pressure and gravity parts per label (worker L303, L317), and the driver saves the matching JVP parts (L172, L178).
- **Kinetic (fixed + elimination): agreement within 1e-3 for every mode; about 1e-5 is expected.** At fixed S the kinetic factor k = (Ft)·(D̄t) is exactly affine in α, so this is a near-exact real-data check of k̇, S*, the conjugation, the mass weights and test-set equivalence. Synthetic agreement was 2e-14 to 1e-10.
- **Pressure (determinant + inverse) and gravity: within 5% for m1, m2 and m4.** Any other outcome is INCONCLUSIVE and goes to option O1 below. It is not a FAIL.
- **Speed elimination.** The m0_radial kinetic-part secant equals −H0·(ds(α)−ds0)/α exactly (synthetic 1e-13 to 1e-11), while the JVP's part is −H0·dS (core L180). This checks dS using already-pinned files. It is informational at one α, because a second-order ds term enters at relative size α|dds2|/|dds|.

**(c) Informational only at one α:**
- the whole-residual comparisons (L201-203);
- the m0 azimuthal and vertical gravity parts;
- the m0_radial kinetic part described above.

**O1 (root's option).** A second finite-worker trial would decide (c). The worker rejects α ≤ 0, so a central difference would need a worker change; one-sided options suffice:
- α = 1e-6, which cuts second-order contamination about 100×;
- α/2 with Richardson extrapolation, 2·S(α/2) − S(α).

The V002 trial took about 6 min with a 2.6 GB peak.

## How root should read the launched result

- **The real F3 identity base is not axisymmetric** (correction from J4; an earlier helper inference was wrong). The pinned finish.json identity mode residuals are gravity-only: 6.1e44, 9.7e44, 3.3e42, 1.1e45, 4.0e42 and 6.7e42 J for m1..m6, against a radial scale of 4.5e47 J. Kinetic and pressure parts are at roundoff. Consequences:
  - **These rows carry real first-order terms:** the m0_azimuthal and m0_vertical gravity JVPs, and the radial rhs (hence dS).
  - **These remain exactly zero by geometry, and therefore are not evidence:** Hdot, the Σ JVP, the m0 kinetic_fixed_S and pressure parts, and kinetic_S_elimination in the modal and m0-azimuthal/vertical rows.
- **m0_radial whole-residual comparison:** about 1.0 by construction (tangent = rhs − H0·dds ≈ roundoff). Use the part-level and self-check items above instead.
- **Scope: identity linearization and one direction only** (core L3; driver L1-5). The derivative this checks is not the next Newton step.
  - The candidate direction folds the affine map near α of order 3e-3 ((1−minJ)/α = 366). Only about 0.3–1% of the modal residual can be removed along it.
  - A nonlinear solve needs generic directions, a non-identity linearization, m=0 map directions for the Σ constraints (core L105, L183-184; spec L36), and declared row scaling across the J, N and kg rows (plan item D3).
