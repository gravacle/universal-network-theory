## Driver vocabulary and counted-pair evidence

The JSON includes every syntactic raise and status assignment in the two pinned driver source files plus the inspected serial solver, parallel solver and worker. Superseded driver clones are retained with locations, not represented as live. NGC live dispatch is ngc:9183–9216 to strict clone 8989–9102; DDO live handlers are ddo:3558–3597.

COMPLETED and COMPLETED_INVALID are completed outcomes, not interruption failures. REFUSED and BLOCKED are nonphysics. FAILED and FAILED_AT_STAGE are uncounted unless affirmative cause evidence establishes a named model outcome. Both drivers aggregate any stage-child nonzero exit, including signals, into StageFailed (1825–1864). Their generic catch records exception type/message and traceback in result, while finish contains status/reasons/result SHA but no structured stage/failure code. Route-A mapping treats any converged flag other than True as ROUTE_A_NO_FIXED_POINT (1883–1964), so that label alone must not authenticate malformed or missing evidence.

Clean ITERATION_BUDGET_EXHAUSTED is a model nonconvergence candidate under the unchanged scientific iteration budget. FAILED_SOURCE_PREPARATION catches ValueError from column solve/metric; it is only a conditional candidate until the exact exception origin is reviewed. Unknown transitive errors remain uncounted. The vocabulary is a root-review draft: no generic ValueError or FAILED allowlist is certified. The requested complete runtime model-code certification therefore remains limited by CAP-04; the syntactic inventory is complete for its declared files.

Monitor receipt pins driver/spec/monitor and result bytes, records exit code (negative values identify POSIX signals), stop reason and driver status. It does not hash finish or stdout/stderr; driver stage_records carry exit and request pin but do not hash stage logs. A245 pair evidence must authenticate finish/result association, named model stage/status/code and exception origin, plus solo/spec identity, on both attempts. Pin a cause record and any consulted worker failure/log bytes. A printed stderr tail without a source digest is insufficient. Monitor/result custody loss is never model invalidation.
