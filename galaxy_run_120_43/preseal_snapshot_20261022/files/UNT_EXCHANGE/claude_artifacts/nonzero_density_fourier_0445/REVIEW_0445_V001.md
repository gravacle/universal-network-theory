## Notes (non-blocking)

1. **J0 guard in the contraction.** The contraction's guard against J0 substitution fires only when an exact-zero argument (k_perp = 0) is present. Without one, a caller-injected provider that substitutes J0 would pass silently. The sibling provider closes this gap: it binds `jn` by order, checks J_n(0), and refuses a jn/j0 alias. So the root should inject the sibling provider and require `status == 'READY'`.
2. **Narrow interruption window.** A KeyboardInterrupt delivered between line 281 (`retained[a:b] = values`) and line 282 (`mask[a:b] = True`) would leave non-NaN rows with the mask False. The interface says those rows are NaN. The mask is authoritative, so no wrong value can be committed. Only the description is imprecise.
3. **Strict `mode` type.** `mode` accepts only a Python int; numpy integers are rejected. This is documented. Integer-dtype R, z, w and k arrays are accepted and cast to float64 without the 2^53 exactness check that the provider applies.
4. **UNTESTED: provider throughput at project scale.** Evaluation is a Python loop over unique arguments, about 0.33 µs each by the author's timing. Deciding test: the root times one realistic wave chunk before launch.
5. **UNTESTED: libm jn above my tested range.** I tested libm jn accuracy up to x = 2718.28; the provider author's tests reached 1e5. Deciding test: compare max(k_perp)·max(R) for the actual wave grid against the tested range.
6. **Placement belongs to the root.** The module returns only the scalar (nk,) increment. The root must embed it as `delta[:,0,0]` and multiply the cached full10 response once, as v004 does with `unit*delta[:,0:1,:]`. The interface states this correctly, and no dk/(2π)^3 factor is added.
