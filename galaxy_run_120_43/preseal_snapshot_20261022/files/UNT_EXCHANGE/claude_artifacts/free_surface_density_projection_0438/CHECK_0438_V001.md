## Notes (none blocking)

1. **Singular-block reporting.**
   - Singularity is detected through LAPACK's exact zero pivot (LinAlgError).
   - For an exactly singular block with one zeroed column, the SVD diagnostic gave condition numbers of 1e17–1e18 rather than inf.
   - A block that is nearly but not exactly singular still solves and returns large coefficients. This follows the spec, which allows no tolerance.
2. **Overflow edge case.**
   - If W·V overflows (|W·V| > ~1.8e308), the assembled M gets NaN off-block entries (0·inf).
   - The module then fails closed before any block solve, with completed_blocks=0 and failed_block=None, even though earlier blocks could have been solved.
   - This is conservative and only reachable at overflow magnitudes.
3. **Dtype and provenance rules.**
   - Wider than the spec: float16/float32 real arrays and complex64 xi are accepted, with exact upcasts.
   - Stricter than the spec: whitespace-only provenance is rejected.
   - Real-dtype xi is rejected rather than promoted, as the interface states.
4. **Conjugation is checked only on the private core.** The public API requires real V/VR/VZ, so conjugation could only be exercised through `_compute`. The static AST check confirms explicit `.conj().T` for V, VR and VZ.
