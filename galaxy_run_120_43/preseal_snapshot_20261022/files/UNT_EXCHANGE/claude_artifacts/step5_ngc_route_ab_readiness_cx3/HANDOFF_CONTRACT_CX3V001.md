This is a proposed target-free custody handoff for Claude2 to adopt. It does not establish V007 or step-4 scientific admission. The caller supplies the handoff SHA256 from an external, trusted root record; computing a hash of an arbitrary input does not confer admission. All actual admission and certificate claims remain UNTESTED here.

The selected filler is `tools/fill_step5_cx3v002.py`; its full byte pin is in STEP5_REGISTRY_CX3V001.json. POLICY_CX3V001.json is locked into that source by its full digest. Its pinned templates, coordinate declaration, NGC slots, driver and fallback registries are all checked from bytes before output. The unchanged source spec and coefficient/source inputs are checked too. The tool neither executes a driver nor edits a registry.

Claude2 supplies a strict handoff with exactly the fields shown in HANDOFF_SHAPE_UNFILLED_CX3V001.json. Replace every dollar placeholder; that shape file is deliberately unusable as a real handoff. Use mode ADMITTED, root_admission STEP4_ADMITTED_UNDER_ADOPTED_V007 and the externally adopted V007 record pin. Until Claude4 accepts r007, driver_branch is r006_fallback and driver_acceptance_pin is null. To select r007, root provides its accepted review record pin; the filler byte-verifies it but does not interpret scientific review prose or authenticate authorship.

The source_export_pin points to a root-attested, target-free JSON export with exactly schema, mode, target_free, coordinate_pin, admitted_points. The schema is UNT_STEP4_TARGET_FREE_ADMITTED_EXPORT_CX3V001; mode ADMITTED; target_free true; coordinate_pin equals the policy coordinate pin. Each admitted_points entry contains exactly log_index, u, theta_natural copied from the actual native calibration admitted_points record. Export only these fields: no observed arrays, projection velocities or target-derived NGC fields. The root handoff is the admission trust anchor for this export. Source custody back to the full native step-4 record must be retained by root; this lane must not open protected run paths to reconstruct it.

The selected log_index must be present exactly once, integer and nonnegative. Every exported point is validated: all 29 coordinate names, four varying u entries in [0,1], finite numbers excluding booleans, coordinate bounds, fixed values at trial, and u-to-theta consistency. Nonfixed consistency uses relative tolerance 1e-12 and zero absolute tolerance; thus gamma_over_Eref near 1e-16 cannot be accepted through a large absolute epsilon. Duplicate JSON keys, arbitrary added fields, unsupported driver/policy changes, bad pins, prohibited paths and nonfinite values refuse.

Physical mapping is fixed: Eref_J=Eref_base_J; ell_F_m=ell_F_m; common_scale_s=common_scale_s; gamma=gamma_over_Eref*Eref_base_J; entropy remains the registered 64/121. NGC distance and inclination come from the pinned NGC slot trial values 13.8 Mpc and 72 degrees. The DDO154 distance is validated as an admitted DDO nuisance and is never copied into NGC geometry. Other shared fixed parameters are validated against the coordinate declaration because the driver/source pins embed them rather than expose them. A65 changes only the coefficient grid at the same admitted shared point. All static numerics and source fields come from the pinned template cited by the handoff's policy; no free parameter CLI flags exist.

certificate_pins contains exactly eps_certificate and lo_certificate. Pending sentinels remain explicitly pending; real replacements must be byte-pinned records supplied by the same root handoff. Filler pin checking does not establish EPS/LO/GQ scientific coverage. Root must rerun dry-plan/preflight on concrete certs and retain the actual NGC91, K32/N3-prime and M_s96 gate records. A change to M_s128 or other numerical policy requires a new reviewed policy/template successor; it is not silently borrowed from DDO P128/M_s128.

Both schema interfaces currently plan the integrated route-A then route-B chain. The B template's pending route-A sentinel is produced by that call. Select one A or B interface for a point/grid; launching both repeats the calculation. Binding supplied route-A custody into a B-only replay is outside this locked policy and requires a separately reviewed successor; the five native route_a_inputs fields are seed, attempt_directory, checkpoint_directory, identity_sha256, result_sha256.
