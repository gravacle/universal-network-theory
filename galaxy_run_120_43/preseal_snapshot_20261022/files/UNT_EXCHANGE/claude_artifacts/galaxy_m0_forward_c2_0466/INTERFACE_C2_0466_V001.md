## 4. Identity substitution: the only changes to reused code behaviour

Each stage runs as `python -I -B driver _stage request.json`, with single-thread env and a fresh process. The shim works like this:

1. It executes the stage from the exact bytes it hashed.
2. It replaces only the listed module globals.
3. It wraps `importlib.util.spec_from_file_location`, so that listed dependency modules get their globals replaced after their own code runs. Each patched file is re-verified from bytes. A missing target name is an error.

| Where | Global | Per-call value (from bytes) |
|---|---|---|
| reuse worker (`acda989d`), as a dependency in body/offset/columns/rotation/feedback, and as the stage itself for `reference` | `SEED_SHA`, `IDENTITY` | Call seed sha; this call's (or the admitted) checkpoint `IDENTITY.json` identity_sha256, after recomputing its canonical self-hash. |
| body V002 | `REFERENCE`, `DATA_PINS` | This call's reference dir; sha of its start/finish; the monotone source (unchanged pin). |
| offset V003 | `COEFF`, `COEFF_SHA` | Call coefficient grid. |
| columns V001/V003/V005, rotation V001/V005, feedback V002/V004 | `OFFSET_SHA` | sha of this call's offset `finish.json`. |
| column mean V004 | `PINS` (ordered: binding, rotation start, rotation finish, column start, column finish) | Binding `f42c7c65` unchanged; this pass's run files. |
| prep V007 (route A, only for a non-default grid) | `COEFFICIENT`, `COEFFICIENT_SHA` | Call grid. |

Every other pin is untouched and still checked by the stages: worker-version SHAs, `BODY_WORKER_SHA`, `COLUMN_WORKER_SHA`, `ROTATION_WORKER_SHA`, `FEEDBACK_WORKER_SHA`, the reference module sha `81a04b12`, the profile, the monotone source and the binding. Every equation, tolerance and guard is untouched too. Fixed reviewed arguments are wave batch 256, position batch 512, Bessel cache 500000 and mass tolerance 1.1e-8. Γ = 5/3 and σ0 = 11 km/s stay hard-coded in the stages.

The dry-run compares each per-call value against the hard-coded value. For both reproduction specs, all identity overrides are NO-OPs: 50/50 and 56/56. The only two "differs" entries are the PINS of the extra LE1/LE2 observations.

## 5. Truncation mask: a declared NUMERICAL CHOICE, not physics

- **`cube`:** reproduces current behaviour exactly. No hook is installed.
- **`sphere`:** keeps |k| ≤ kmax.
- **`cylinder`:** keeps k_perp = √(kx²+ky²) ≤ kmax, with the disk axis as chart z, and keeps every k_z of the cube.
- **`kmax`:** defaults to the grid edge and must not exceed it.

The mask works only as a 0/1 weight mask on the existing composite nodes. The reviewed `prepare()` forms `weighted_response = dk_weight/(2π)^3 · x̃` node by node, so zeroing a weight is exactly zeroing that node's response row. Its own guard rejects dk ≤ 0, so the mask is applied to the produced rows:

- the cache-module `prepare` output in the offset stage (unit response and offset response);
- the checkpoint `_get` of the G4 total `prepared_weighted_responses` blob only (matched by file sha) in route-B stages.

All later totals are linear per node (total + unit·Δ), so they inherit the mask. Sources are never masked. Both masks are invariant under k → −k, so the stages' reality guards still apply.

Two scope limits:

- **Route A is not masked.** Its own fixed point, and therefore the K0, body and roots, stays cube-truncated. A full-chain mask would need hooks inside route A's own preparation; that is UNSUPPORTED.
- **Kept fractions** on the default 72³ grid at 2/kpc: sphere 92.2% (344048 nodes), cylinder 97.1% (362592 nodes).

## 6. Brackets (column enthalpy brackets are numerics, but they move the root at the 1e-5 to 1e-8 level)

The saved chain derived every bracket table from the previous solved Hc as `[f_lo·H, f_hi·H]`. I verified this bitwise for all 72 columns of every pass:

- FS: nominal [1.5125e8, 3.025e8], plus 11 manual corrections [3.025e8, 3.17625e8] for indices 5–9 and 45–50.
- RFS: 0.8/1.2 × H_FS, plus index 71 at 0.8/1.01.
- LE1: 0.4/0.9 × H_RFS.
- LE2 and LE3: 0.8/1.1 × the previous pass.

The two modes:

- **`pinned_controls`:** passes the saved controls files themselves, so the input hashes are identical.
- **`rule`:** generates the tables. Defaults are as above. `fs_absolute_overrides`, `rfs_factor_overrides` and `le_factor_overrides` are declared up front, not conditional, so no retry happens.

Column V001 accepts only one global bracket per run, so the driver groups FS indices by bracket into separate runs. A bracket miss fails that column. The rotation stage then fails ("Missing complete72"), and the call ends FAILED_AT_STAGE with outputs preserved. The fixed factors may not bracket at other entropy factors. `le_first_factors` is a parameter.

## 7. Column-parallel mode (`column_workers` N ≤ 12; requires `rule`)

Columns within a pass are independent. The per-column loop builds fresh line objects, the modules hold no state, and `einsum(optimize=False)` is deterministic. Splitting a pass into N contiguous index chunks therefore gives identical column arrays. The rotation stages sort by index, so their arrays and all downstream values are identical to serial. The column JSONs differ only in path fields.

Two constraints:

- **The final LE pass is always serial.** Column-mean V004's reviewed guard requires a single run with 72 completed columns.
- **With a convergence bound, all LE passes are serial**, because each must be observable.

Memory is about 0.62 GB per column worker, so 12 workers need about 7.5 GB.

Bitwise identity of serial and parallel holds by construction but is UNTESTED on real data. The deciding test: run the same rule spec with `column_workers` 1 and 12, then compare the `rotation_array_content_digests` and rows in `result.json`.

## 9. Monitor and campaign

**Monitor:**

```
root_monitor_c2v001.py --driver D/galaxy_m0_forward_c2v001.py --driver-sha256 H --spec S --outdir O --receipt R \
  --wall-cap-s F --rss-cap-bytes N --output-cap-bytes N [--poll-s 1]
```

- It refuses if O exists, if R or `R.launch.json` exists, or if the driver pin mismatches.
- It runs the child in its own session with single-thread env.
- Each poll samples RSS summed over the whole process tree (`ps -A -o pid,ppid,rss`) and total bytes under O.
- On a cap it sends killpg TERM, then KILL.
- Receipt fields: command, pins (driver, spec, monitor), caps, child pid, exit, elapsed, peak RSS, peak and final output bytes, samples, stop reason, driver status, `result` {path, sha256}, `retries: 0` and a self-hash.
- `verify_receipt()` re-checks the self-hash, the pins and the result hash from bytes.

**Campaign:**

```
campaign_c2v001.py --campaign FILE.json --campaign-dir DIR [--resume]
```

- Each call runs in `DIR/call_NNNN/{spec.json, out/, RECEIPT.json}`.
- At most `max_concurrent` (≤ 12) calls run at once, and `max_concurrent × column_workers` must be ≤ 12.
- Resume skips verified calls (RESUMED_OK, RESUMED_FAILED); failed calls are never rerun.
- An unverifiable directory is DIR_EXISTS_UNVERIFIED and is never touched.
- After the campaign wall cap no new call starts.
- Results come back in input order and are also written to a new `campaign_summary_<utc>_<pid>_<ns>.json`.

Suggested caps for one real serial call: wall 10800 s, RSS 3 GiB (route A peaks at 1.14 GB), output 8 GiB. Route A alone writes 3.66 GB and a full call about 5.6 GB.

## 11. Supported, unsupported and blockers

**Supported:**

- DDO154.
- Eref, ℓ_F, γ and s.
- Entropy factor.
- Coefficient grid by {path, sha256}, including the candidate.
- Composite k-grid and kmax.
- Cube, sphere and cylinder truncation (route-B field only).
- P passes, an optional bound, rule or pinned brackets, column workers, admission of a saved prefix, and the reference comparison.

**Unsupported or blocked:**

1. **Route-A convergence must land on iteration 4.** Every route-B stage hard-codes `iteration_0004`, and the reference worker requires `start['iteration']==4`. A parameter point whose route-A fixed point converges at any other iteration ends BLOCKED. A reviewed successor that accepts the converged iteration as a parameter is required.
2. **Distance and inclination.** The D/4.3 radial scaling (0.93953) and the cos66/cos64 stellar re-facing (0.92784) are baked into `GALAXY_RADIAL_SOURCE_REFERENCE_V001.json`, and no code applies them. The 12 query radii (4.04 Mpc) and sin66/sin64 are fixed in `DDO154_COLUMN_MEAN_REFERENCE_BINDING_V001.json`. Only 4.04 Mpc and 66° are accepted. Supporting other values needs a reviewed source builder and binding.
3. **NGC3198 is unsupported** and the config entry carries the reasons:
   - every route-B stage hard-codes 72 columns, the 16×32 geometry and `galaxies['DDO154']`;
   - the body stage pins the DDO reference;
   - the rotation stages pin the DDO monotone source;
   - there is no 43-row column-mean binding;
   - there is no NGC route-A seed.
4. **Full-chain truncation mask** (inside route A): unsupported (§5).
5. **Parallel final pass:** blocked by the reviewed column-mean guard (§7).
6. **s as a pure 1/s rescale:** not a route-B forward call (§3). The whole chain reruns.
7. **Other hard-codings, unchanged:** σ0 = 11 km/s, Γ = 5/3, 16 azimuths, 32 nodes per column, and the GL4 roster (the body stage requires `source_gauss_order == 4`).
