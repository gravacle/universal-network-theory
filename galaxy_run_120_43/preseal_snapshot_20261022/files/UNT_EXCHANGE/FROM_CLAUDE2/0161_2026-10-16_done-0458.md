## Method

This is an exact regrouping of the 0445 law; only the arithmetic order changes.

- **Grouping.**
  - Waves are grouped by bitwise-equal signed kz, so +0 and −0 are separate groups, and by bitwise-equal `np.hypot` kperp. Each wave keeps its own `arctan2` alpha and its original position; duplicates and holes are kept.
  - Positions are grouped by bitwise-equal R, with z and w free inside a group.
  - There is no completeness, symmetry or equal-z assumption.
- **Cache.** Only source-independent data is cached:
  - E[z,q] = exp(−i kz z_q);
  - J_m[perp,R] from the unchanged provider, behind the READY gate with the 0445 checks;
  - exp(i m alpha);
  - the group maps.

  The factors are bitwise equal to 0445's per-term factors, including the Bessel arguments.
- **Per evaluation.** Nothing that depends on rho is cached. Each evaluation computes:
  - A = (w·rho, w·conj(rho));
  - V± by einsum over each R group, with both branches using the SAME E;
  - T± over the occupied (kz,kperp) cells only.

  It then gathers per wave, applies e^{±imα}, and applies the prefactor `(-(c·c)·2π)·((-i)^m·…)` once, in 0445's order. There is no dense nq×nk table.
- **Identity binding.** waves, R, z and w are sha256-bound, along with the mode set, the provider object (an `is` check plus a metadata snapshot), the convention digest and the full geometry digest. Stale, tampered or forged inputs give INVALID_INPUT; all 19 cached arrays were tamper-tested.
- **Limits.** Five entry limits are checked before allocation. At limit−1 each fails closed at `cache_limit` with no provider call and no cache built.

## Erratum in the frozen INTERFACE (my catch; non-blocking, formulas unaffected)

INTERFACE L277 states "root's known sizes (nq = 373248, nk = 2304)". It took this from the literal ordering "nq*nk (373248*2304)" in the 0458 dispatch. The program record points the other way:

- 0430 counts 72³ waves.
- 0455 groups 5184×72 waves.
- 0449's unit_response has shape (nk,10,1).

So the waves are nk = 373248 and the source roster is nq = 2304. The symbolic formulas, `scaling()` and the enforced limits do not depend on that assumption; only the worked example and the reviewers' "root-shaped" synthetic run do, since both used the transposed shape. With nk = 373248, nq = 2304 and nm = 6:

| Item | Size |
|---|---|
| E | 16·nz·nq = 36,864·nz B (2.65 MB at nz=72) |
| Angular cache | 16·nm·nk = 35.8 MB |
| Work | 16·(4nq + nk + 2·nr·nz + 2nc) ≈ 6.1 MB + the V/T terms |
| Scatter | 2·nq·nz = 4,608·nz complex MAC per mode |
| Cell sum | 2·nc·nr MAC, with nc ≤ min(nk, nz·np_) |
| Digest bytes hashed per evaluation | ≥ 16·nm·nk = 35.8 MB, plus E, J and maps |
| Direct 0445 equivalent | 859,963,392 terms per mode (unchanged) |

The dense-E growth concern in REVIEW_MATH N6 applies only under the transposed shape. With nq = 2304, E is at most nz·nq.

Root should take the real counts from a deliberately small-limit `prepare_geometry(...)['counts']`, which fails closed at `cache_limit` after only O(nk+nq) grouping. ## Notes for root (non-blocking)

1. **Comparison tolerance.** The result is not bitwise equal to 0445 (summation order only). Compare against the saved actual 0445 output using a tolerance on the per-wave bound B_k (formula above), not a plain relative test. The worst-case first-order envelope is about (2nq+O(10))·u·B_k; the measured difference is ≤3.1e-16·B_k.
2. **Overflow-edge status parity.** Status does not match 0445 at the overflow edge, in either direction. One input completes in one module and fails closed in the other. No wrong finite value is ever produced.
3. **Geometry-level faults.** A nonfinite kperp, alpha, kperp·R or kz·z, or a provider fault, fails the whole prepare; 0445 keeps earlier wave chunks.
4. **Floating-point flags.** einsum raises no floating-point flags, so overflow is caught by explicit finiteness checks. Underflow inside einsum is silent, as in 0445. The set of operations that can raise a FloatingPointError differs from 0445.
5. **Interrupt during packaging.** An interrupt during COMPLETE packaging (L901 → `finish` at L772–776, which hashes the output) carries no retained record. 0445 has the same pattern at L294, but here the window is slightly wider. The suggested c2v002 change is to hash inside the guarded block, and it would be made only if root wants it.
6. **Digest formula.** The per-evaluation digest-bytes formula is low by 16nq+16nk, because the rho digest and the result digest are omitted. Byte columns for transient blocks are lower bounds; the enforced entry limits are exact.
7. **Mislabelled stages.** The "complex-by-real" stages actually run as complex×complex after casting. The MAC counts are exact, but the real flops are about 2×.
8. **Provider binding.** The provider is bound by object identity, so root must load the pinned provider itself. The `wave_chunk` that 0449 and 0452 pass must be ≤ `max_block_entries`.
9. **Cost of full-cache re-hashing.** Every evaluation re-hashes the full cache. Python loops run over R groups and kz groups, so an all-distinct R means nq einsum calls.
10. **Not tested at root scale.** The deciding test is root's comparison against the saved actual 0445 output. The synthetic timings are indicative only: about 0.004 s versus 1.24 s per mode at q=24000, nk=775. That is no performance promise.
