## 0413 items (review confirmed all five against the V004 text)
1. **Arrays and counts.**
   - Per-chain arrays are registered in `series` before sweep 0.
   - A measurement count is incremented only after all four row writes.
   - Burn-in is never stored.
   - Only `[:n]` prefixes are returned, with no zero padding.
   - A guard keeps short chains out of `_analyze`.
2. **Budget hook placement and behaviour.**
   - The hook is checked before and after every operator call, around validation and adapter reads, between jumps, before held-mark replays, before array allocation, between sweeps and moves, and before analysis.
   - It consumes no RNG, and every check runs before `rng.exponential`.
   - A stop gives `status=incomplete` with `incomplete_reason=INCOMPLETE_BUDGET`. A validation failure gives `failed` or `unsupported`, which is distinct.
   - An unfinished proposal is abandoned, not counted as a rejection or a measured state. `move_open` is recorded and `resumable=False`.
3. **Root policy.** The 150 s / 900 MiB policy is documented only. There are no clock, memory or threshold constants in the code. The risk that one operator enumeration overruns the reserve is stated.
4. **Progress records.** Small records go to the caller sink at every stage, at chain start, after every completed sweep and at stop. There is no in-module I/O and no per-sample journal.
5. **Partial return.** It returns `ok=False`, skips `_analyze`, and labels the prefixes as diagnostics only. Completed runs keep the analysis, thresholds and `_sokal_tau`, `_rhat` and `_mode_outputs`, all AST-identical to V003.

## Notes for root before launch
- **N1 (recommended).** The `chain_start` record is emitted after `np.zeros`. A hard kill during the chain-0 allocation therefore looks the same as a kill during initial-path building. A pre-allocation record with the planned bytes would separate the two, since n_meas·(n_u²+n_u+n_r)·8 + n_meas·8 needs no RNG. This could be added as a one-line follow-up; it is not done in V004.
- **N2.** The sampling `try` catches only `_Stop`. An in-process `MemoryError`, for example under an address-space limit, escapes and loses the committed prefixes. The caller should keep C·n_meas·(n_u²+n_u+n_r+1)·8 bytes well under 900 MiB.
- **N3–N11:**
  - A cap stop also returns INCOMPLETE_CAP prefixes, which are state-dependent.
  - A partial `accepted_in_measurement` count can include an unfinished sweep.
  - The sink costs some time per sweep.
  - A hook or sink exception ends the run as `failed` with no prefixes.
  - Some failed exits send no stop record.
  - Prefixes are views.
