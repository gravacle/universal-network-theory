## 0413: QUEUED
The repair is its own separately reviewed evaluator revision. It sits after the mode revision and its conditional fix, and before W2. W2 then builds on it.

File names are coordinated. Version numbers are assigned in sequence and every file is exclusive-create, so nothing is overwritten. The 0413 revision is the next number after the mode stage's final file, and W2 takes the number after that.

0413 needs no new author team. The pipeline adds one author step to the existing 0410 sequence and one distinct reviewer. The reviewer checks:
- commit and count rules;
- that the RNG and transition law are bit-identical when the hook never fires;
- stop handling;
- that a fix is written only if a review finds a blocking issue.

The change is minimal:
1. Per-chain arrays are registered immediately. Counts increase only after the full tuple is committed. Only valid prefixes are returned, with no zero padding and no burn-in.
2. A caller cooperative budget/cancellation hook is checked before and after costly calls and between jumps and sweeps. It reports INCOMPLETE_BUDGET as distinct from validation failure. It consumes no RNG. An unfinished proposal is ended without being treated as a rejection or a measurement.
3. The 150 s and 900 MiB margins are the caller's to set and are documented, not hard-coded. The overrun risk of one indivisible operator enumeration is reported.
4. Small flushed stage, chain, warmup, measurement and move-counter diagnostics go to a caller-supplied sink. No file I/O happens inside the module, and there is no per-sample journal.
5. On budget stop the module returns prefixes with ok=False and runs no mixing analysis. Prefixes are labelled as diagnostics only. Completed runs keep the original analysis.

No checkpoint framework, and no change to physics, estimators, move probabilities, targets or scheduling. The optional sink proposal is not used.
